The Workflow

One run of the bench: seed a workspace, let the agent train the student for its budget, score what it wired in. The margin over the untrained student is the result.

The run, end to end

  1. Launch: agents/run_sandbox_modal.sh --track easy codex_kimi3 fav2 24 — scaffold, task, budget in hours. The Docker runner takes the same arguments.
  2. Session: the agent iterates its loop (next section) until timer.sh runs out.
  3. Record: the trace, chain of thought, learning log, audit verdict, and workspace archive land on the lab-observatory volume and appear on this dashboard.
  4. Score: the operator runs python3 submission/eval.py --input tasks/<task>/test.json --output answers.json, stages the answers as runs/<tag>/budget_50/candidates.json, and judges them with bench.py judge (pinned gpt-5.6-luna, 3 votes per answer, bootstrap confidence interval).
  5. Margin: submission score minus the base floor (the untrained student through the reference harness, same judge). Both rows go to runs/LEADERBOARD.jsonl.

The agent's loop

Training moves the weights; the harness moves how the weights are used. The margin usually needs both, and weight moves compound: SFT on generated data first, then preference pairs (DPO) or RL with a judge-based reward once SFT plateaus. A run that only rewrites the harness leaves the student itself unchanged.

What is in the workspace

Everything the agent can see, at the moment it starts:

workspace/
  AGENTS.md    the assignment: objective, submission contract, rules
  timer.sh             remaining wall-clock budget
  .env                 judge-service pointers (LEARNING_AGENT_JUDGE_URL/TOKEN), Modal env — no provider keys
  task/                the ONE task, copied in at setup: task.md, sys.txt,
                       corpus/ (per track), dev.json (easy)
  model/               the untrained task model's weights (pinned snapshot,
                       downloaded in at setup)
  toolbox/
    TOOLS.md           the toolbox manual: workflow, specifications, rules, catalog
    data_tool/         method cards (.md) + dedup_decontam, mix (runnable)
    training_tool/     pinned packages: axolotl (SFT + DPO), training_gym (RL)
    eval_tool/         gen_eval, rubric_eval (judge service client)
    harness_tool/      answering programs: completion_qa, react_loop, react_*, mini_swe_agent
    inference_tool/    vllm_serve, sglang_serve
    gpu_tools/         gpu_launcher.py, gpu_sandbox.py + Modal how-to docs
    api_clients/       judge/LLM client library
  submission/          the scoring surface: eval.py (contract), agent.py, serve.py
  runs/                LEARNING_LOG.jsonl (empty), GPU_LOG.jsonl (written by tools)
  agents/, bench/      run machinery + prompt material (injected at seed time)

Not in the workspace: held-out test.json, other tasks, the judge and scoring code, integrity pins, this dashboard's code, and any provider API key.
