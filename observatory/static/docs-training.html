Training Pipeline

Training changes the weights of the task model. The agent trains by running the packages in training_tool/ — axolotl for SFT and DPO, training_gym for RL. Every method produces the same output: a merged full-model directory that the evaluation serves directly. The agent chooses the data, the method, and the hyperparameters, and composes each package's own commands.

Training-row formats

Training data is JSONL. There are exactly two row shapes. Do not mix them unintentionally:

{"question": "...", "answer": "..."}   # answer in the task's answer format
{"messages": [ {"role": "...", "content": "..."}, ... ]}   # full chat transcript
  1. QA mode — each question/answer row becomes one chat exchange under the task's verbatim sys.txt system prompt. The prompt is read from the task config and injected exactly as the evaluation harness injects it, so train-time and eval-time framing match byte-for-byte.
  2. Trace mode — if any row carries messages, the whole file trains as chat transcripts, with the loss masked to assistant turns only. This is how search behavior is trained: multi-turn ReAct traces come from data_tool/agentic/react_trace_gen.
  3. Open-book rows — a row may carry its own note field, or --note-file injects one shared note into every row's system message. The note is prepended exactly as the eval harness prepends it.

Training uses the packages directly

There are no wrapper scripts around the trainers. The agent drives the packages in toolbox/training_tool/ directly: it reads each package's own docs, composes that package's commands, and runs the GPU work through toolbox/gpu_tools/gpu_launcher.py, which starts Modal H200 sandboxes with the standard volumes mounted.

Checkpoint output contract: every trained checkpoint must end up at /out/models/<tag>/merged on the volume lab-out. Serving and scoring both read checkpoints from that path.

Namespace discipline: /out/models/ is shared by all runs; since 2026-08-13 each run writes under its own /out/models/$LEARNING_AGENT_RUN_ID/ namespace (the runner exports LEARNING_AGENT_RUN_ID and gpu_launcher.py injects it into every sandbox). Runs launched before then used flat /out/models/<tag> paths — a tag collision once overwrote another run's checkpoint — so old artifacts keep their flat paths and only new runs namespace.

What the agent must record

# one line per experiment in runs/LEARNING_LOG.jsonl:
{"ts": "<iso>", "kind": "checkpoint", "tag": "...",
 "model_path": "/out/models/<tag>/merged", "dev_score": <float>,
 "what": "<what was done>", "why": "<why it was tried>", "artifacts": [...]}
# kinds: checkpoint | submission (a wiring change) | note (an observation)
  1. Write one JSON line per experiment to runs/LEARNING_LOG.jsonl. The kind field is one of: checkpoint (a trained model), submission (a wiring change), or note (an observation).
  2. what and why are required on every line. The log is the only record of the agent's reasoning that survives the run.
  3. Record every checkpoint. The observatory's dev-score column reads harness results when they exist and otherwise falls back to the log's checkpoint entries (older runs used CHECKPOINTS.jsonl). A checkpoint that is not in the log is invisible to both the operator and the dashboard.
  4. run.sh warns when a run ends with an empty log.

Observed costs

  • SFT smoke test: 1×H200 ≈ 10 minutes, plus a one-time ≈18 GB base-model download into lab-hf-cache.
  • Real SFT runs at fav2 scale (10²–10³ rows, ≤16k tokens): minutes, not hours. Agents typically fit 3–16 such training rounds into a run.
  • RL end-to-end smoke test (2 rollout iterations): 2×H200 ≈ 15 minutes. Real GRPO runs are the most expensive operation in the toolbox.
