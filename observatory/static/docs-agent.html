The Learning Agent

A frontier model running a CLI coding harness in a container. Its workspace is the seeded learning_agent_workspace/ directory plus one task. The model decides what to do; the harness executes tools and runs the session loop.

The workflow

One run, end to end:

  1. Launch. agents/run_sandbox_modal.sh --track easy codex_kimi3 fav2 6 — scaffold, task, budget in hours. Seeding builds the workspace (the learning_agent_workspace/ folder, the run machinery, the one task, held-out files deleted), assembles the prompt from the pinned template, and starts the agent.
  2. Make training data. The agent implements a method from the toolbox/data_tool/ cards or invents one, and cleans every dataset with data_tool/pool/dedup_decontam.
  3. Train, or improve the harness. It drives a pinned package in toolbox/training_tool/ on H200s. Merged checkpoints land at /out/models/<tag>/merged.
  4. Evaluate. It answers its dev set through submission/eval.py's own pipeline and judges the answers with toolbox/eval_tool/rubric_eval.py — the judge service serves the same pinned judge that scores the submission.
  5. Record and wire. One line per experiment in runs/LEARNING_LOG.jsonl; the current best system stays wired into submission/eval.py at all times. Repeat from step 2 until the budget ends.
  6. Score. The operator runs the submission on held-out questions and reports the margin over the untrained student (Evaluation & Scoring).

Where it runs

Never on the operator machine. A session is one container: the Modal app lab-agent (standard; image pins @openai/codex@0.145.0 and opencode-ai@1.18.8) or a local Docker twin (agents/run_sandbox_docker.sh). A Modal session lives on the lab-agent-workspace volume at <task>/<session>/: workspace/ holds everything the agent writes, logs/ holds the CLI's own session state. Run artifacts (trace.jsonl — commands, outputs, and the model's chain of thought — plus prompt.txt, audit.json) are archived to the lab-observatory volume when the run ends.

Scaffolds

A scaffold is a directory under agents/ with a solve.sh (launch the harness with a given model) and a trace parser. Model and harness are independent axes; adding a model on any OpenAI-compatible endpoint is a config file (agents/lib/kimi_k3_endpoint.env, glm52_endpoint.env), not new code.

The shim (agents/lib/responses_shim.py): Codex speaks only the Responses API, and the endpoint's server cannot serve function tools on it, so the shim translates Codex's Responses traffic to the endpoint's chat wire on localhost. It also translates the model's reasoning_content into Responses reasoning items, so the chain of thought lands in trace.jsonl as ordinary thinking events — collapsed on the run page like tool calls.

Budget

  1. timer.sh in the workspace tells the agent how much wall-clock remains; the prompt says to stop at zero.
  2. Re-prompt: if the model ends its session with budget left, the scaffold resumes it ("You still have Xh Ym remaining") until under 30 minutes remain.
  3. Hard kill: agents/run.sh kills the whole process group at budget + 5 minutes.

What a run leaves behind

The agent's own record is runs/LEARNING_LOG.jsonl: one line per experiment, what and why required, dev score and artifact paths attached. The run warns if it ends with the log empty. Everything else is captured mechanically: the full command trace, the chain-of-thought record, GPU usage (runs/GPU_LOG.jsonl), and a deterministic audit that checks the trace for held-out data access.
