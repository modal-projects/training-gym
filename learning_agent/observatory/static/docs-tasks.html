Tasks & Tracks

A task is a domain corpus plus a question set and an answer format. A track sets how much of that the agent is given at launch. A task exists if and only if tasks/<task>/task.yaml exists. That file is the single per-task configuration read by the bench CLI, the judge, the integrity pins, and the runners.

Two archetypes exist. qa tasks are scored through the reference search harness and the rubric judge. agentic tasks are scored through the rollout evaluator (bench.py score dispatches on the archetype field) by the environment's own verifier; no LLM judge is involved in scoring them.

Anatomy of a task

tasks/<task>/
  task.yaml     # the per-task config: archetype, corpus path + version pin, dev/test
                #   paths, sys prompt path, file glob, secondary metric, session defaults
  corpus/       # the domain corpus (gitignored; distributed separately; content
                #   tree-hash pinned in bench/pins.json)
  dev.json      # agent-visible on easy: rows of {id, topic, question, gold_answer,
                #   rubric, evidence} — gold answers plus a weighted rubric
  test.json     # held-out counterpart of dev.json, same format — physically deleted
                #   from every workspace
  sys.txt       # the student's verbatim system prompt at evaluation time
  task.md       # the task description the agent reads
  brief.md      # hard-track acquisition manifest: names the primary sources and the
                #   normalization contract so the corpus can be re-fetched byte-identically
  ROUNDS.md     # legacy iteration log (pre-2026-08-11 runs; runs/LEARNING_LOG.jsonl
                #   is the record now)

Track selection happens at launch time through prompt assembly. There is no track-specific code path.

  1. One pinned AGENTS.md template contains a single <MEASURING_YOURSELF> slot.
  2. At launch, the slot is filled from the pinned bench/tracks/<track>.md block.
  3. On medium and hard, the withheld files are physically absent from the workspace — the same treatment as test.json — so the agent cannot recover them by searching.
  4. The assembled prompt never names the track and never mentions that the repository is a copy.

Base floors

Each task's margin is computed against a base floor: the score of the untrained student answering through the frozen reference harness (Evaluation & Scoring). The floor is scored once per judge configuration and re-judged whenever the operator changes the judge. A submission and its floor must be scored by the same judge; otherwise the margin is not comparable.

Adding a task

  1. Create tasks/<task>/ with the files above; write task.yaml (a task exists if and only if this file exists).
  2. Keep held-out material out of the corpus by construction: build the evaluation file and the corpus as two separate artifacts — see Integrity.
  3. Register nothing else: the CLI, pins, and runners discover the task from task.yaml. Then run python bench.py freeze (a new task changes the set of pinned files) and commit the updated pins deliberately.
